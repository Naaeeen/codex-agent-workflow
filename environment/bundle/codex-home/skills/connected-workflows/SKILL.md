# Connected work

Use the user's existing tools first. The current preference is Outlook for mail
and calendars, Drive/Docs/Sheets/Slides for Google files, Notion for workspace
context, and GitHub for repository work. Native local document tools remain useful
for draft/render/verification. Do not duplicate a project into a second tracker
merely because another connector exists.

Discover the actual tools and target account/workspace before choosing actions.
The dated inventory {{CODEX_HOME}}\workflow\connected-capabilities.json
records metadata/empty-search checks, not a permanent connection guarantee. In
this setup Outlook, Drive, Notion and GitHub reads worked; Linear did not. Do not
assume that an exposed tool means installed/authorized, or that a read proves
every write permission. Search for missing plugins only when a task needs them.

For meeting preparation: identify the specific calendar event, read only relevant
linked documents, reconcile decisions and draft the agenda. For project work:
ground the issue/spec, identify the repository, execute with the project workflow,
then prepare a source-backed update. For research: use private workspace sources
when relevant and public search for public facts; do not put private content into
public queries. Read each provider's focused skill for file identity, import,
formatting and sharing semantics.

Separate reading/drafting from effects. Send mail, invitations, comments, task
updates, sharing or publication only when the user authorized that concrete
action; existing scoped authorization counts. Do not add a confirmation loop to
already authorized routine work. Scheduled/recurring work uses the native
automation action when requested, not an ad hoc hidden background process.

Check returned identifiers, destination/account and actual write/readback when
applicable. Preserve source links and distinguish a draft from a sent/published
result. The connector is an access path, not permission to inspect unrelated data.
