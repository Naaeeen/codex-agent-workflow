# Bounded delivery

Read current instructions, entry docs, Git state, manifests and CI before assigning work. Define the user outcome, acceptance and preserved unrelated work. Use the project's existing tracker and runtime.

Keep dependent steps sequential. Delegate independent research, exploration, implementation or review only when it helps. Discover available role and model controls; preserve the user's main settings and choose task-appropriate cost/effort without fixed model names or unmeasured savings claims.

Each worker packet contains goal, raw sources, constraints, explicit allowed files/modules (or read-only), dependency inputs, actual checks, return format and stop condition. Tell every writer that the workspace is shared and others' changes must be preserved. Do not assign overlapping files by default.

For consequential work, request fresh-context independent review with user requirements, current sources/diff, evidence and rubric. Exclude preferred conclusions and earlier verdicts from the discovery pass. Do not withhold required product context. Label shared-history follow-up accurately.

Parent verifies returned findings, resolves conflicts and disagreements, integrates changes, runs affected checks and inspects the final scope. Spawning a reviewer does not establish review completion. If independent review is unavailable, report NOT RUN and the residual gap without waiving stricter gates.

Example: worker A owns serialization; worker B researches browser encoding behavior read-only; parent owns download integration. A reviewer checks the resulting source and artifact against the user contract.

At a useful phase boundary save objective, latest constraints, decisions, owned/changed files, check results and failures, active processes, blockers and the next action. Resume from verified state; do not restart completed work just because context compacted. Use only the client's supported compaction mechanism.

External writes, remote jobs, credential changes and publishing retain their actual authorization requirements. A handoff or worker role grants none.
