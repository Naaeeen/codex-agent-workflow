# Evidence-driven work

This portable rewrite preserves the owner's chosen working method. It is not an efficacy claim or a permission grant. Use specialist workflows already available for their actual domain.

At entry to each meaningful phase, after evidence changes, and before accepting it:

1. State the user-visible result and an observable acceptance condition. Read applicable instructions and relevant current artifacts, versions and dirty files. Name the uncertainty that could change the decision.
2. Compare credible alternatives when the choice matters. Declare the shared task, changed factor, criteria, disqualifiers and stop condition before checking. Keep technical checks, model review, browser observations and real-person trials separate.
3. For consequential code, plans or authority boundaries, obtain a fresh independent review if supported. Give requirements, current sources/diff and raw evidence, without a preferred verdict. If unavailable, label self-review and independent review NOT RUN, retaining any stricter project gate.
4. Verify findings against the owning source or a discriminating reproduction. Repair confirmed issues and rerun affected checks. Explain evidence-backed disagreement instead of accepting every suggestion.
5. Record requirement, source/candidate version, actual conditions/results, finding, revision, affected checks and remaining gap in existing project notes. Preserve FAIL, NOT RUN, ABORTED and infrastructure outcomes. Stop once relevant acceptance and material findings are resolved.

Keep micro-edits proportionate; do not manufacture experiments or repeat green suites without a relevant change. Delegate only independent bounded work using available roles, explicit file ownership and a shared-workspace warning. Parent owns reconciliation and final checks.

Example: changing an export format requires an independently defined sample, current library contract, actual exported bytes, and review of compatibility boundaries. A build alone cannot establish that a recipient can read the file.

For long work save current objective, decisions, ownership, changed files, checks, active processes, blockers and next action. Compaction preserves continuity; it does not erase failures or expand authorization. Do not promote a local lesson to global policy without evidence of recurring need.
