# Source-led research

Infer the decision and scope from the request and available facts. Ask only for information that materially changes the result; continue independent work meanwhile.

1. Inspect current local facts and installed versions. Split a broad question into bounded independent subquestions only when helpful.
2. Discover available search, documentation and connected-source tools. Prefer capabilities already present. Provider names in examples are not guaranteed callable APIs; no new installation, payment or private upload is implied.
3. Search for evidence that could resolve or overturn the decision. Read decisive primary sections, limitations and version dates. Record the actual source URL/version and whether access was full, excerpt-only or unavailable.
4. Separate documented fact, observed local behavior, inference and untested hypothesis. Resolve contradictions by checking definitions, versions and conditions. Multiple copies of one article are not independent corroboration.
5. Cite material claims beside the supporting source. Return the decision, reasons, rejected alternatives where relevant, uncertainties and next useful check. Stop when material questions are resolved; search counts are not a quality target.

For parallel research, give read-only agents independent questions, raw evidence, constraints and a completion condition. Parent checks claims used in the final answer.

Example: for a dependency migration, compare the installed version's contract with target release notes and a focused compatibility test. “The docs describe cancellation” does not prove the current service stops a running job.

Do not claim unread sources were reviewed. If a key check is impossible, state its real cause, a provisional decision and a concrete falsifier rather than presenting uncertainty as established behavior.
